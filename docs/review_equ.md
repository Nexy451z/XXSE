## 1. 分かったこと

### 1.1 枠 = 8 バイトヘッダ + 長さフィールド付きペイロード（40/40 で成立）

```
+0x00 u32 クエスト ID
+0x04 u32 ペイロード長 (942 または 169)
+0x08 u8[ペイロード長] ペイロード（先頭 4 バイトは再びクエスト ID）
残り (0x800 - 8 - 長さ) は全ゼロ
```

検算結果（40 枠すべて）:

* `u32@0x04` は 942 または 169 のみ。**同じ形式なら全枠で同値**（1020xxx は 28/28 が 942、1120xxx は 12/12 が 169）。
* 最終非ゼロバイト位置（枠内、0 起点）は 942 形式で 928〜949、169 形式で 169〜171。
  `8 + 長さ - 1`（= 949 / 176）を超える枠は **0 枠**。
* `u32@0x08 == u32@0x00` は **40/40**。
* 未使用枠（25, 41, 42, 43, 44）は 8 バイトヘッダも含め全ゼロ（長さ 0）。

→ 2 番目の u32 は「クエスト固有の数値」ではなく **ペイロード長**である（1.2 で構造的に裏づける）。

### 1.2 サイズは「ヘッダ長 + 固定長レコード × 5」で厳密に説明できる

| 形式 | 分解 | 実測 |
|---|---|---|
| 1020xxx | 32 + 5 × 182 | **942**（一致） |
| 1120xxx | 29 + 5 × 28 | **169**（一致） |

1020xxx 側の境界の実測根拠:
支給品リストの先頭は必ず「支給専用秘薬(1724) ×2」= バイト列 `BC 06 02` で、
これが 1020xxx のペイロード内 **0x73, 0x129, 0x1DF, 0x295, 0x34B** に現れる。

* 差分はちょうど 182（0xB6）。
* 0x73 = 0x20 + 0x53。すなわち「ヘッダ 32 バイト + レコード k×182 + レコード内オフセット 0x53」。
* 5 個目は 0x34B = 0x20 + 4×182 で、0x34B + 182 = 942 = ちょうどペイロード末尾。
  **5 本目が途中で切れているのではなく、最初から 0x34B に始まる**（以前「末尾が切り詰められている」ように見えたのはこのオフセットずれのせい）。

→ **固定長レコードの配列**（レコード長はクエスト形式で決まり、途中で伸び縮みしない）。1 枠 = 5 レコード。

### 1.5 +0xB3 は武器種（EQUIPMENT_TYPES のインデックス）— 28/28 で成立

`crates/mhnx-core/src/gamedata.rs` の `EQUIPMENT_TYPES`
（7=Great Sword, 8=Sword and Shield, 9=Hammer, 10=Lance, 11=Heavy Bowgun, 12=IGNORE THIS,
13=Light Bowgun, 14=Longsword, 15=Switch Axe, 16=Gunlance, 17=Bow, 18=Dual Blades,
19=Hunting Horn, 20=Insect Glaive, 21=Charge Blade）と照合した。

1020xxx の 28 枠**すべて**で次が成立:

1. レコード 0〜3 の +0xB3 は **4 つとも相異なる**。
2. レコード 3 は必ず遠隔武器（11 / 13 / 17）、レコード 0〜2 は必ず近接武器。
3. レコード 4 の +0x9B（8 枠）の中身が、レコード 3 の武器種と一致する。
   * 11 (Heavy Bowgun) → 弾（実測 ID 16 種: 101,102,103,104,105,109,110,111,112,113,115,116,117,120,121,126）
   * 13 (Light Bowgun) → 弾（実測 ID 21 種: 101〜107,109〜113,115〜118,121〜125）

## 2. 否定した仮説と根拠

| # | 仮説 | 判定 | 根拠（実測） |
|---|---|---|---|
| 1 | 「+0x04 の u32 はクエスト固有値（難易度など）」 | **否定** | 1020xxx の 28 枠すべて 942、1120xxx の 12 枠すべて 169。ペイロード長と 40/40 で一致し、`8+長さ` 以降は全ゼロ |
| 2 | 「942 と 169 は偶然」 | **否定** | 942 = 32 + 5×182、169 = 29 + 5×28 が厳密に成立。さらに 1020xxx の 28 枠でレコード境界 0x73+182k が一致 |
| 3 | 「枠の後半に前のクエストの残骸が残る」（クエスト枠でありがち） | **否定** | 40/40 で `8+長さ` 以降は 1 バイトも非ゼロが無い |
| 4 | 「レコードは可変長（アイテム数で長さが変わる）」 | **否定** | 1020xxx 全 28 枠でレコード 5 本の開始位置が同じ。未使用エントリは固定配列のゼロ埋め（ゼロの後ろに非ゼロ 0 件） |
| 5 | 「先頭から 0x73 までがヘッダ、以降がレコード」（当初の読み） | **否定** | 5 本目が 0x34B+99 で切れて見えた。正しくはヘッダ 32 バイト、レコード開始 0x20+182k。0x73 = 0x20+0x53 |
| 6 | 「装備枠のアイテム列は .sup と同じ 4 バイト {item,count,slot}」 | **否定** | 4 バイト刻みで読むと直後のレコード/フィールドが壊れる。3 バイト刻みでのみ 24 枠 / 8 枠が 0x48 / 0x18 バイトに厳密に収まる |
| 7 | 「5 × 9 バイト = 防具 5 部位（頭胴腕腰脚）」 | **未確定（否定的証拠あり）** | 86/140 レコードで 5 個の u16 が**完全一致**、5 個すべて相異なるレコードは **0/140**。通常の防具セットなら 5 部位は別 ID になるはずで、この読み方には合わない |
| 8 | 「1 枠 = 1 装備セット（1 レコード）」 | **否定** | 1 枠に 182 バイトのレコードが 5 本入る（うち 4 本が武器種を持つ） |
| 9 | 「+0xB3 は難易度やフラグ」 | **否定** | 1020xxx の 28 枠で「レコード 0〜3 は 4 値が相異なり、レコード 3 だけが 11/13/17」が 28/28。加えてレコード 3 の値とレコード 4 の弾/ビン種別が 28/28 で一致。武器種以外でこの整合は説明しにくい |

## 3. まだ分からないこと

1. **プロローグの 6 つの u32**（107522, 215040, 460800, 38400, 25600, 12800）の意味。
   全 40 枠で同値なので「形式定数」であることは確実だが、値の由来は不明。
2. **5 × 9 バイトエントリの u16（25〜1239）が何の ID か**。
   アイテム表の範囲にも入るが、`JWL_I_DS`（2638〜2899）とは重ならない。
   装備（武器/防具）の ID 空間かどうかは、装備名テーブルがリポジトリに無いため未判定。
3. **+0x07 / +0x08 / +0x09〜+0x1C / +0x4A / +0xB4 / +0xB5** の意味。
   +0x4A は {0:42, 2:38, 8:60} で、slot 20 以降（ID 1020015〜1020029）がほぼ 8、slot 0〜13 がほぼ 0/2 という
   **クエスト群との相関**だけが見えている。
4. **レコード 4 の位置づけ**。武器種バイトを持たず（0 が 25 枠、2/4/6 が各 1 枠）、
   弾/ビンの 8 枠だけを持つ。「共通の追加支給品」なのか「5 本目の武器選択肢」なのか決められない。
   なお +0xB3 が 0 以外になる 3 枠（23, 24, 28）は +0xB4/+0xB5 も非 0 になる。
5. **1120xxx（169 バイト）レコード 28 バイトの中身**。3 つの {u16, 0} 以外は未解読。
6. **武器選択肢が 4 つである理由**（訓練クエストの仕様か、データ側の上限か）。
7. **アイテム ID かアイテム ID でないかの切り分け**（1.4 の +0x09 の 10 個の u16 など）。

## 5. 実装メモ（そのまま使える形）

1020xxx 形式（1 枠 = 5 レコード）:

```
枠ベース(絶対)   = 36 + 0xB280 + 0x1049F4 + slot * 0x800      # slot 0 = 1,113,240
ペイロード       = 枠ベース + 8                                # = 1,113,248
レコード r       = ペイロード + 0x20 + 182 * r                 # r = 0..4
  +0x00  u8       (常に 0)
  +0x01  u16 x3   装飾品 ID（0 または 2642..2837）
  +0x07  u8
  +0x08  u8
  +0x09  u16 x10  未解読
  +0x1D  9B x5    { u16 a, u8 b, u16 c, u16 d, u16 e }
  +0x4A  9B       先頭 1 バイトのみ使用（0/2/8）
  +0x53  3B x24   { u16 item, u8 count }  ← 固定 24 枠
  +0x9B  3B x8    { u16 item, u8 count }  ← 固定 8 枠（弾/ビン）
  +0xB3  u8       武器種 (EQUIPMENT_TYPES index)
  +0xB4  u8, +0xB5 u8  未解読
```

書き換え時の注意（実測にもとづく）:

* アイテム列の「未使用枠」は 0 でなければならない（非 0 の残骸は 1 件も無いので、消すときは 0 埋めする）。
* 個数は最大 99（実測最大 99）。
* アイテム ID は 2991 未満に収める（実測最大 1728）。範囲外は ITEM_NAME_LIST から外れる。
* 枠の `+0x04` の長さは形式ごとに固定（942 / 169）。書き換えで長さを変える必要は無い。

# カスタムクエストが動かないときの対処

MHXX のカスタムクエストは「反映されない」「フリーズする」「マルチで受注できない」という
報告が非常に多いです。ここでは原因がはっきりしているものを整理し、
mhnxeditor が自動で見つけられるものは自動で見つけます。

---

## 1. mhnxeditor が自動で見つけるもの

クエスト画面で L ボタン（PC 版は「このクエストをチェック」）を押すと検査します。

| コード | 深刻度 | 内容 |
|---|---|---|
| one-player-only | 注意 | 参加条件1 が 0x2F（1人限定）。マルチで受注できない |
| reward-dummy-only | エラー | 報酬ファイルが rem_000000 だけ。報酬が反映されない |
| reward-dummy-item | エラー | 報酬の個数・確率だけ設定してアイテムIDが 0。フリーズの原因 |
| reward-too-many | エラー | 報酬の個数が 99 超 |
| reward-probability | エラー | 確率が 100 超 |
| mib-id-mismatch | エラー | .mib のクエストIDとファイル名が食い違い |
| mib-size / rem-size / sup-size | エラー | ファイルサイズが規格と違う |
| qdl-missing | エラー | questLink (.qdl) が無い |
| gmd-missing | 注意 | クエスト文章 (.gmd) が無い |

「1人限定」はその場で解除できます（実機版は A ボタン、PC 版は解除ボタン）。

検査ルールは公式クエスト 141 件すべてで試して、誤って警告を出さないことを確認しています。
ネット上に出回っている「支給品は10個まで」といった数字は公式データでは守られていないため、
警告ではなく参考情報として出すだけにしています。

---

## 2. 1人限定（最重要）

症状: マルチプレイで「受注に失敗しました　クエストデータが正しくありません」

原因: Quedixx は保存するたびに questData_xxxxxxxx.mib の 0x1A を 0x2F（1人限定）に書き戻します。
終了時にも「2F以外だと変更が保存されていません」と判定して書き直します。

直し方（mhnxeditor を使う場合）

```text
1. クエスト画面で L を押してチェック
2. 「1人限定」の行を選んで A（PC 版は解除ボタン）
3. X で .arc に書き出す
4. 書き出した .arc は Quedixx で開き直さないこと（開くと 0x2F に戻されます）
```

直し方（バイナリエディタを使う場合）

```text
questData_xxxxxxxx.mib を開いて アドレス 0x1A を 0x2F 以外にする
  例: 0x00 = 条件なし、0x07 = HR8以上
その後 Quedixx を開かずにフォルダを .arc に圧縮する
```

## 3. 報酬が反映されない

- 報酬は rem_xxxxxx というファイルに入っています。
- rem_000000 はダミーで、ゲームは読み込みません。ここを編集しても無意味です。
- Quedixx の報酬タブで「報酬ID」をクリックすると編集するファイルを選べます。
  ファイルタブで読み込む報酬ファイル名と一致していないと反映されません。
- 確実なのは、元のクエストで使われている報酬ファイルをひとつずつ虱潰しに編集する方法です。

---

## 4. フリーズする

| 症状 | 原因 |
|---|---|
| クエストクリア後に黒画面 | 報酬ファイルの設定ミス、またはダミーアイテムを報酬に入れた |
| 大連続の2匹目で停止 | 小型モンスターを「2回剥ぎ取りできる種類」に変えた（特に極園で発生） |
| 獰猛化で停止 | 獰猛化が存在しないモンスターに獰猛化を設定した |
| アトラル・カの形態移行で停止 | 通常のイベントクエストをベースにした。G★4 のアトラル・カをベースにする |
| 目的地「極園」で停止が多い | 極園は不安定。他のフィールドで試す |

大連続クエストを正しく作るには、次の2つが必要です。

1. クエスト種類を「大連続クエスト」にする
2. アイコン/ターゲットタブで ターゲット1 = 大連続 / 対象「なし」 / 数「0」 にする

モンスターの設定では 状態と難易度は 0 のまま、匹数は 1 が安定します。

## 5. そもそも作れないもの

- G級クエストは新規に作れません。置き換えられる枠が上位までしかないためです。
  （中身のランクを G にすることはできます）
- ミラバルカン / ミラルーツ / アトラル・カ はエディタ上で「不明」と表示され、バイナリ編集が必要です。
  報告例: 「0A」がミラ系の管理値で、隣のバイトが 01 で ミラルーツ、02 で ミラバルカン。
- モンスターの「？？？？？」系（ぶんどりアイテム）を報酬に置いても、鑑定後に応急薬になります。
  装備として扱われるためです。
- 大型モンスターの同時出現は 2 体までです。3 体以上は小型枠を使う必要がありますが MHXX では非対応です。
- 出現パターン 8 は補充形式です。2 体から始まり、1 体倒すと 1 分後に次が出ます。

## 6. マルチプレイがどうしても通らない場合

3DS 版では、テキストを 1 文字変えただけのクエストでもマルチで弾かれるという報告があります。
これはクエストデータの中身ではなく、ゲーム側のチェックによるものです。

海外のユーザーが共有しているチートコード（3DS 用、Luma のコード欄などに貼る）:

```text
[カスタムクエストマルチプレイヤー修正]
004518E8 E3A06001
00451BE8 E3A00001
```

**このコードは検証済みです**（MHXX 更新データ 1.4.0 の実コードとバイト単位で一致）。
詳しい解析は [mp_reverse_engineering.md](mp_reverse_engineering.md) を参照してください。

- 0x004518E8 は本来 @@movne r6, #0@@（失敗フラグを落とす命令）→ @@mov r6, #1@@ に固定
- 0x00451BE8 は本来 @@mov r0, r5@@（戻り値）→ @@mov r0, #1@@ に固定

3DS のチートファイル（Luma3DS）は次の場所に置きます。

```text
SD:/luma/titles/0004000E00197100/cheats.txt

[Custom Quest Multiplayer Fix]
004518E8 E3A06001
00451BE8 E3A00001
```

タイトル ID @@0004000E00197100@@ は**更新データ 1.4.0** のものです。本体のみの環境では別アドレスになります。

**Switch 版には、そもそもこの制限が無い可能性が高いです。**
根拠: 掲示板では 3DS だけが弾かれ「動作確認は Switch のみ」と書かれている /
Switch 版のコードに 3DS 版の判定パターンが 1 つも存在しない。

そのため Switch 版のチートコードは作っていません（根拠なく書き換えると起動しなくなります）。
まず Switch 実機でマルチプレイに貼ってみて、弾かれたときだけ解析を再開してください。

**オンラインで使うとチート行為になります。自己責任で。**

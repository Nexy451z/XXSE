## 2. 一番大きな発見: スロット位置はセーブに入っている

我々は 0x126474 / 0x244C34 / 0x3633F4 を定数として持っていましたが、
このアプリはセーブから読んでいます。

```js
this.slot_offsets = [
    u32(data, 0x10 + off),   // off = 0x24 (Switch/MHGU) または 0 (3DS)
    u32(data, 0x14 + off),
    u32(data, 0x18 + off)
];
```

実セーブで検証したところ、完全に一致しました。

```text
body+0x0C = 0x0000B280   -> DLC セクション位置（我々の値と一致）
body+0x10 = 0x00126474   -> スロット 1（一致）
body+0x14 = 0x00244C34   -> スロット 2（一致）
body+0x18 = 0x003633F4   -> スロット 3（一致）
```

我々の mhnx-core は既にこの方式でした（OFF_SLOT_BASE / OFF_DLC_SECTION をセーブから読む）。
つまりこの点は同等以上で、検算の裏が取れた形になります。

### スロットの内訳

```text
1 スロット = 0x11D088 (キャラクタ本体) + フッター
  MHXX : フッター 0x1738 -> 合計 0x11E7C0
  MHGU : フッター 0x283C -> 合計 0x11F8C4
```

フッターは叫び（自動チャット）の領域で、1 件 0x3C バイト（MHGU は 0x68 バイト）。
我々は stride をそのまま使っていたので実害はありませんが、構造が把握できました。

## 3. 取り込んだ 4 点

### 3.1 装備箱とお守り（新規実装）

slot+0x62EE は我々が「装備箱 72000 バイト」として中身を見ていなかった領域です。
レビューにより、これは**武器・防具・お守りの共用箱**（2000 レコード × 36 バイト）と判明しました。
先頭バイトの下位 5 bit が種別で、6 がお守り、1〜5 が防具、7〜20 が武器です。
実セーブには 188 個のお守り、601 個の武器・防具、1211 個の空きがありました。

```text
+0x00  u8   種別 = byte0 & 0x1F。6 がお守り
+0x0C  u8   スキル1 ID（1 始まり）
+0x0D  u8   スキル2 ID
+0x0E  i8   スキル1 ポイント
+0x0F  i8   スキル2 ポイント
+0x10  u8   装飾品スロット数
```

72000 バイトの直後が我々の OFF_PALICO_EQUIPMENT (0x17C2E) と完全に一致したので、
レイアウトの裏が取れました。

新規モジュール mhnx-core/src/charm.rs:
- decode_box / encode_charm / clear_charm
- スキル名は skills.rs（このアプリから 306 件を抽出して生成）

### 3.2 配信オトモ 50 体（新規実装）

body+0x2A から 50 × 0x144 バイト。オトモ ID は +0x5F、名前は先頭 32 バイト。

これは以前「謎の名前フィールド」に見えていた場所です。実セーブで確認:

```text
#1  id 0x64  ぽかぽか
#2  id 0x65  ミケゴールド
```

### 3.3 本体オプション（新規実装）

```text
body+0x28    明るさ（0..255 の生バイト。実セーブは 48）
body+0x29    振動
section-2    3D 表示の無効化   <- DLC セクション位置から逆算
section-1    スライドパッドプロ
```

最後の 2 つをハードコードせず DLC セクション位置から逆算したのが改良点です。
MHGU はセクションが 1 バイト後ろ（0xB281）なので、固定値だと壊れます。

### 3.4 性別の二重管理（バグ修正）

我々は性別を slot+0x23B4B から読んでいましたが、
キャラクター選択画面が使うコピーが slot+0x2A に別途あります。

```text
slot+0x00  名前（選択画面用）       <- 我々も書いていた
slot+0x20  プレイ時間（同）         <- 我々も書いていた
slot+0x24  所持金（同）             <- 我々も書いていた
slot+0x28  ハンターランク           <- 我々も書いていた
slot+0x2A  性別（同）               <- ★書いていなかった
```

名前・所持金・時間は同期していたのに性別だけ抜けていました。
修正して両方に書くようにし、テストで固定しました。

## 6. 残り 3 点も実装済み（上位互換）

相手が上回っていた 3 点をすべて取り込みました。

### 6.1 配信オトモの書き込み

データ（EN 27 体 / JP 57 体、各 0x144 バイト）を dlcats.rs に取り込みました。
ID はレコード内 +0x5F の連番で、名前は先頭 32 バイトに入っています。

```text
mhnx cats                          60 体の一覧（EN/JP 名つき）
mhnx cat-add <system> jp 0x66      坊ニャ春道 を追加
mhnx cat-del <system> 3            枠 3 を空ける
```

GUI では言語と ID を選んで「追加」、「外す」で削除できます。
すでに入っている ID は「導入済み」と表示され、二重追加は拒否されます。

### 6.2 スロット単体の入出力（.saveslot）

```text
mhnx slot-export <system> 1 out.saveslot   1 スロット分を書き出す（1173440 バイト）
mhnx slot-import <system> 3 in.saveslot    スロット 3 に読み込む
```

サイズはセーブから計算した stride（MHXX 0x11E7C0 / MHGU 0x11F8C4）を使うので、
形式が違っても正しく動きます。キャラクタ本体のみ（0x11D088）のファイルも読み込めます。
読み込むと使用フラグも自動で立ちます。

GUI ではファイル選択ダイアログから操作できます。

### 6.3 お守りの編集

GUI の「設定/オトモ」タブで、お守りの一覧・削除・書き込みができます。
スキルは ID で指定し、名前がその場で表示されます（Poison など 306 種）。

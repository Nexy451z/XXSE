## 2. 各項目

### 2.1 アイテム追加（#1）— できるが導線が悪い

**手順（実際にクリックした順）**

1. `jksv_system.bin` を `itemtest.bin` にコピー。
2. `MHNXEDITOR_OPEN_SAVE=itemtest.bin / OPEN_TAB=items / ITEM_SELECT=2242 / ITEM_FILTER=秘薬` で起動（2242 は 0 始まり = 箱 #2243、このセーブの最初の空き）。
3. 詳細パネルの候補「28 秘薬」をクリック（クライアント座標 920,159）。
4. 「上書き保存」をクリック（300,18）。
5. 終了 → ファイルを Python でデコード → 再度 exe で開いて確認。

**結果**

- クリック後: `選択中: 箱 #2243 ID 28 個数 1`、一覧 `2242 件 → 2243 件`、下部 `● 未保存 / 箱 #2243 を 秘薬 に変更しました`。→ `shots/21_item_picked.png`
- 保存後: `○ 変更なし / 書き出しました: …itemtest.bin（元のファイルは …itemtest.bin.bak に退避）`。→ `shots/22_item_saved.png`
- デコード結果: slot 2242 が `(0,0) → (28,1)`、非空 2242 → 2243。`.bak` は元と SHA-256 一致。
- 再起動（フックで同じ箱を選択）: `2243 件 / #2243 ID 28 個数 1`。→ `shots/23_item_reopen.png`

**分かりにくさの原因（現行行番号）**

- 空き枠は既定で非表示: `item_show_empty` の既定 false（`app.rs:131` 付近）＋ フィルタが `id == 0` を除外（`app.rs:1186-1198`）。
- このセーブの空きは **末尾 2243〜2300 番**に固まっているため、「空きスロットも表示」を入れて表の最下部までスクロールしないと空き行に触れない。
- ツールバーは折り返さない `ui.horizontal`（`app.rs:1131-1177`）で、「空きスロットも表示」が右端で切れる（`shots/20_item_select_empty.png` では「空きス…」までしか見えない）。
- 表の列は `70 + 80 + remainder + 90`（`app.rs:1207-1210`）。サイドバーが広いときは「個数」列が画面外へ出る（`shots/02_items.png`）。
- 「追加」専用ボタンは無く、空き行を選んで詳細パネルから名前検索する必要がある。

**修正提案**

- 詳細パネルに「空き枠へ追加」ボタン（`items.iter().position(|s| s.id == 0)` を選ぶ）を置く。
- `item_show_empty` の既定を true にする、または「空き 58 枠」をツールバーに表示してクリックで末尾へジャンプ。
- ツールバーを `horizontal_wrapped` にし、表の列幅を中央ペインに合わせて縮める（個数は固定 90 pt をやめる）。

### 2.2 お守り編集（#2）— できるがポイントが触れない

**手順**

1. `charmtest.bin` を用意し、`OPEN_TAB=charm / CHARM_SELECT=224` で起動。
2. 右側エディタの「装飾スロット」の `●` をクリック（1493,142）。
3. 「適用」をクリック（1321,305）。
4. 「上書き保存」をクリック（300,18）。
5. 終了 → `mhnx.exe charms charmtest.bin 1` で確認。

**結果**

- 一覧の 224 行が `[3 slots]` → `[---]`（slots=0）に変化。→ `shots/35_charm_slot_set.png`, `shots/37_charm_saved.png`
- CLI: `#224 [---] 属性会心 +6 / 達人 +10`（元は `[3 slots]`）。スキルとポイントは保持。
- 保存メッセージに `.bak` への退避が出ている。

**問題点**

- **スキル 1/2 のポイント DragValue は 260 pt 幅のコンボの右**にあり（`app.rs:2794-2814`）、1518 px のクライアントでは x>1518 で画面外。ポイントを変えるにはウィンドウを広げるかサイドバーを狭めるしかない。
- 「空き枠に新規作成」（`app.rs:2892-2900`）は **スキルを 0 で渡す**ため、編集中のスキル構成を無視して空のお守りを作る。空き枠に作るだけなら「適用」でも `Save::set_charm` がテンプレート複製で作れる（`save.rs:599-610`）。
- 削除ボタンは確認も Undo も無い（`app.rs:2769-2771`）。

**修正提案**

- スキル行を「スキル名コンボ」と「ポイント」で改行するか、エディタ幅を 360 pt 固定から広げる。ポイントをコンボの前に置くだけでも解決する。
- 「空き枠に新規作成」は現在の入力値で作る（`set_charm` にそのまま渡す）。またはボタンを廃止して「適用」に一本化。
- 削除に 1 段の確認、または Undo を付ける。

### 2.4 クエスト編集（#4）— できる

**手順（実際にクリックした順）**

1. `questtest.bin` にコピーし、`MHNXEDITOR_OPEN_QUEST=1010005` で起動（クエストタブが開く）。
2. 1518x1053 のクライアントになるようウィンドウを 1536x1100 / 位置 (0,-260) に置き、.mib のフィールド一覧をスクロールせず表示。
3. 「制限時間」の値をドラッグ（クライアント 1170,916 から +30 px）→ 50 → 70。
4. ウィンドウを (0,0) に戻し、「セーブに書き戻す」（1252,84）をクリック。
5. 「上書き保存」（300,18）をクリック。
6. 終了 → `mhnx.exe dlc-extract questtest.bin extract 1010005` → `arc-mib`。

**結果**

- 画面: 制限時間 70（`shots/75_q_edit2.png`）。
- 保存ファイル: 元と 111 バイト差分。範囲は `0xF89C` と `0xFC60`、`0xFF5B-0xFFC8`（DLC セクション 0xB280 内）。
- 抽出した `q1010005.arc`（1833 B）の `.mib` ダンプ: `0x16 time_limit 70`。タイトルも保持。
- 無変更で書き戻した場合は保存ファイルがバイト一致（= no-op が保証されている）。

**問題点**

- **.mib を編集しても下部が「○ 変更なし」のまま**。`dirty` を立てるのは「セーブに書き戻す」だけ（`write_arc_to_save`）。フィールド編集（`app.rs` の `write_u32` 呼び出し群）では立たない。ユーザーは「変更したのに未保存表示が出ない」と感じる。
- 1518x817 の既定サイズでは、.mib のフィールド一覧も「.mib の変更を .arc に反映」も画面外（外側の `ScrollArea` と内側 420 px の二重スクロール）。今回は縦 1100 px のウィンドウで回避した。
- 反映ボタンを押さなくても書き戻し時に flush される（`write_arc_to_save` が `store_arc_entry` を先に呼ぶ）ので、データは失われない。ただしその仕様は画面から分からない。

**修正提案**

- .mib / .gmd の編集時に `self.dirty = true` を立て、下部に「未保存（クエスト）」を出す。
- 「.mib の変更を .arc に反映」を .mib セクションの先頭（フィールド表の直前）へ移す。二重スクロールをやめ、片方をやめる。
- 書き戻し時に自動 flush される旨をボタンのホバーに書く。

### 2.5 オトモ（#5）— UI は編集可、実クリックの永続確認は未完了

- 表示確認（`shots/80_palico.png`, `shots/82_palico_saved.png`, `shots/90_palico2.png`）: 17 匹。名前は `TextEdit`、レベル・なつきは `DragValue`、系統・修得スキルはラベル（`app.rs:2159-2209`）。
- レベル DragValue を 8 px / 35 px ドラッグしたが値が変わらなかった（幅 45 px の小さいウィジェットで、ドラッグ開始点が外れた可能性）。ウィンドウを画面外に置いて `PostMessage` でクリックする方法も試したが、egui/winit は合成メッセージを受け付けず、ファイルは無変化だった（`palicotest2.bin` は元と SHA-256 一致）。
- 画面を前面に出さない制約のため、ここで実クリック検証を中止した。コード上は `set_name / set_level / set_enthusiasm` を直接呼び、`dirty` を立てる（`app.rs:2160-2216`）。保存経路自体は #1/#2/#4 で実証済み。
- ラベル「なつき」の実体は `ENTHUSIASM = 0x26`（`palico.rs:28`）で、ゲーム内の「なつき度」とは別物の可能性がある（`review_gui_audit.md` §2.5 も同旨）。

**未完了項目**: 「オトモのレベルを変更 → 上書き保存 → 再読込で 74 になっている」の実クリック実証。次回は画面占有の許可が取れたときに、レベル欄の中央（例: クライアント 1035,160）を 40 px 以上ドラッグする。

### 2.7 保存（#7）— できる

- 上書き保存（`app.rs:790`）→ `write_current`（`app.rs:272`）→ `apply_to_save` → `.bak` 作成 → `std::fs::write`。
- 実測: アイテム・お守り・クエストのいずれも、保存 → 終了 → 再起動で内容が一致。`.bak` は元ファイルと SHA-256 一致。
- 保存に載るのはキャラ本体とアイテムボックス（`apply_to_save`, `app.rs:233-251`）。狩猟記録が「変更を反映」を押さないと載らない問題は `review_gui_audit.md` §2.7 / P0-1 のとおり（本追試では未検証）。

## 3. 横断所見（本追試で新たに分かったこと）

1. **.mib 編集で dirty が立たない**（§2.4）。「変更なし」表示のまま閉じると、書き戻していない編集は失われる。
2. **既定ウィンドウが画面より大きい**。1280x820 pt は 125% で 1600x1025 px。1536x864 の画面では右下がはみ出し、ステータスバーが見えない（`main.rs:47-50`）。最大化しても 1536x864 では 1229x691 pt にしかならず、サイドバー 711 pt + 中央 518 pt で厳しい。
3. **サイドバーのタブ列が 1 行の `ui.horizontal`**（`app.rs:898-`）。タブ列の幅（約 691 pt）がパネル幅を押し上げ、中央ペインを圧迫する。ビルドによってはタブ列がパネルからはみ出して中央ペインに重なって描画された（1920x1080 の `shots/90_palico2.png`）。どちらも `horizontal_wrapped` かトップバー移設で解消する。
4. **二重スクロール**（クエストタブ）。外側ページと 420 px の .mib 一覧で、目的のボタンがどちらにあるか分からない。
5. アイテムの空き枠は「末尾に固まっている・既定で非表示・ツールバーのチェックが切れている」の三重苦で、追加に気付きにくい。

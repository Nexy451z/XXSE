## 3. 各論証

### 3.1 系統 0x25（8 種、0 起点）

**実測値**（17 体）: 3(×5), 4(×7), 5(×2), 6(×2), 7(×1)。出現するのは 5 種のみ。

3 系統の独立証拠が一致した：

1. **romfs の説明文インデックスと一致**
   `OtInfoMsg_jpn.gmd`（8 文字列）が系統の説明文で、順序は
   `0:オトモからの信頼が厚いニャ / 1:攻めて攻めて攻めまくるニャ / 2:守りの堅さはナンバー１ニャ / 3:多彩なサポートができるニャ / 4:回復ならなんでも任せてニャ / 5:とにかく爆弾が大好きニャ / 6:狙った素材は逃がさないニャ / 7:ビースト変化で荒ぶるニャ`。
   セーブの 0x60（あいさつ）が**この配列そのまま**の個体があり、**既定あいさつを持つ 10 体のうち 9 体で「あいさつ index == 0x25」が成立**する（外れるのは改造個体 #39 のみ。残り 7 体は配信/自作の自由文あいさつ）。
   例: #0 あいさつ"回復ならなんでも任せてニャ"=index4, 0x25=4 ／ #29 "ビースト変化で荒ぶるニャ"=7, 0x25=7。
2. **GMD のキー名が 8 種を列挙**（`OtMenuMsg_jpn.gmd`）
   `Ot_charisma_Msg, Ot_Fight_Msg, Ot_Guard_Msg, Ot_assist_Msg, Ot_Heal_Msg, Ot_Bomber_Msg, Ot_correct_Msg, Ot_beast_Msg` — **カリスマ/ファイト/ガード/アシスト/ヒーリング/ボマー/コレクト/ビースト**の 8 種で、順序も 0x25 と 1:1。
3. **系統固有の第 1 技と一致**
   各系統の第 1 修得技（+0x38 の先頭）は系統ごとに固定で、romfs の系統説明文が名指しする技と一致する（下記 3.3 の表）。
   ヒーリング=3(真・回復笛), アシスト=20(毒々落とし穴), ボマー=12(大タル爆弾G), ビースト=46(ビースト変化), コレクト=37(ぶんどり)。

> C# の `PalicoForte` 配列（8 件, [0]=Charisma … [7]=Beast）は**正しい**。3DS 版 6 種という前提は誤り（MHXX は 8 種）。
> なお `OtMenuMsg` の系統説明に「**カリスマはフリー装備サポート行動枠が他より 1 つ多い**」と明記がある。

### 3.2 性格・テンション・攻撃系統

* **性格フィールドは無い（確定・否定）**。romfs の全 GMD を UTF-8 走査しても、オトモ関連の「性格」文字列は**モンスター解説以外に存在しない**。ゲーム内の用語は「サポート傾向」（=0x25）と「攻撃系統」（=0x27）。旧 MH4 系の「性格」は MHX/MHXX では系統に統合されている。
* **0x26 = テンション**（C# の enthusiasm）。`OtMenuMsg` のオトモ情報に `テンション`/`Tension` があり、`Lb_OtDoujoMsg` に「修行回数を選択してください（**上限はテンションで決まります**）」とある。
  **実測値は 25 と 99 の 2 値のみ**（Lv64–73 の 3 体が 25、残り 14 体が 99）。99 が上限と推定（100 以上・255 近傍は観測されず、u8 全域を使っていない）。
* **0x27 = 攻撃系統**。`OtMenuMsg` の `SmallOnly, SmallPriority, balance, LargePriority, LargeOnly`（+指定なし）と一致。実測 1–5（0=なし は出現せず）。

### 3.3 技（8+16）とスキル（8+12）

4 ブロックの存在は **空き値のセンチネル**で機械的に確定できる：

| ブロック | 枠 | 空き値 | 一致するテーブル末尾 |
|---|---|---|---|
| +0x28 | 8 | 0 | （装備中：0=なし） |
| +0x30 | 8 | 0 | （装備中：0=なし） |
| +0x38 | 16 | **0x39=57** | 技テーブル 58 件の最終 ID（C# `PalicoSupportMoves[57]="NULL [57]"`）。17/17 で出現 |
| +0x48 | 12 | **0x60=96** | スキルテーブル 96 件（0–95）の**1 つ外**＝ゲームの空きコード。17/17 で出現 |

* 修得技 ID の実測最大は **57（＝空き）**、実データ（空き以外）の最大は 54。修得スキル ID の実測最大は **96（＝空き）**、実データ最大は 81。→ **ID 空間は上表のテーブル長と整合**。
* **装備中 ⊆ 修得** の関係は **17 体中 16 体で成立**（+0x28⊆+0x38、+0x30⊆+0x48）。
  破れているのは **#39「猫」だけ**で、この個体は (a) 系統=ヒーリングなのに第 1 技がアシスト固有の 20、(b) あいさつもアシスト用 index3、(c) 装備スキル 3 件が修得リストに無い、(d) 経験値が Lv70 で 950,215（Lv99 の #37/#41 と同値）——**改造個体**と判断できる。
* **装備中リストがスロット間で書き換わる**ことも確認（#41 は slot0 が全 0、slot1/2 が +0x28 8 バイトと +0x30–0x32 の 3 バイト）。つまり +0x28/+0x30 は「現在の装備」で、ゲームが 3 枠だけ書いた実例。
* **系統固有の第 1 技**（+0x38 先頭、16/17 で系統と一致）:

| 系統 | 第 1 技 ID | 名称（C# 表記） | 根拠 |
|---|---|---|---|
| 4 ヒーリング | 3 | True Health Horn（真・回復笛） | 系統説明「≪真・回復笛の技≫が可能」 |
| 3 アシスト | 20 | Poison Purr-ison（毒々落とし穴） | 系統説明「≪毒々落とし穴の技≫が可能」 |
| 5 ボマー | 12 | Mega Barrel Bombay（大タル爆弾G） | 系統説明「≪大タル爆弾Ｇの技≫が可能」 |
| 7 ビースト | 46 | Beast Mode（ビースト変化） | 系統説明「≪ビースト変化の技≫」 |
| 6 コレクト | 37 | Plundering（ぶんどり） | 系統説明「ぶんどりや採取が得意」 |

* **+0x54/+0x56 の 2 バイト**は「習得パターン ID」で、**17/17 が既知テーブルの値と完全一致**（C# `PalicoActionRNG` 7 種 / `PalicoSkillRNG` 9 種と全一致）。値の意味（どの技を覚えるか）は未解明。
* **装備可能数の目安**（実測＋GMD）: 装備技は最大 5 件（#28）。GMD に「カリスマは他より 1 枠多い」「サポート行動追加の術で +1」とあるため、枠 8 に対し**実際に装備できるのは 3–5 件程度**（推定）。スキル側は実測最大 4 件（#37）で、GMD の「**記憶力**が不足しています」から**点数制**（枠数≠装備可能数）と推定。

### 3.4 固有 ID（+0x5F）と 0x58–0x5E

* **+0x5F は固有 ID（u8）**。#3–#7 と #27 が **0x97,0x98,0x99,0x9A,0x9B,0x9C** を**連番**で持ち、しかもこの 6 体は
  出撃状態 0xE0=**160**（C# 表: "This DLC palico"）、ジョブ 0xE2=8、あいさつがコラボ文（セブン-イレブン／パセラ／JOYSOUND／日本ゲーム大賞 優秀賞記念）、名付け親が配信元（"笑顔の店員"・"カラオケ"・"市原Ｄ"・"小嶋Ｐ" 等）。
  → **「0x97–0x9C は配信個体」という過去報告は正しい**。しかも連番なので「配信個体に振られる通し番号」と判断できる。
* 配信 6 体は 0x58–0x5E が**全て 0**。通常個体は 0x58–0x5E に値が入り、**同一名付け親の個体で 0x58–0x5B が共通**（例 #37/#38/#39 は `E8 CA CC E5` が共通で 0x5F だけ 0/3/5）。→ 0x58–0x5E は固有 ID とセットの**個体識別（作成元/作成バッチ）**と推定。C# の「前オーナー 4B + 系統固有 ID 3B」という解釈は**未検証**（配信個体で 0 になる点は説明できるが、通常個体の値が文字列様のバイト列になる理由が不明）。

### 3.5 装備（+0x100 / +0x102 / +0x104）

* 3 つの u16 は「**オトモ装備ボックス**」の **0 起点インデックス**。装備ボックスは slot+**0x17C2E**、36 B × 1000 件（`Offsets.cs:83`）。
  エントリ構造（実測）: `+0 種別(0=空,22=武器,23=頭,24=胴) / +2 u16 アイテムID / +4 u16 外見ID`。
  ボックス内の使用数は 72 件（武器 58・頭 7・胴 7）。
* **17 体での検証**: 3 枠が指すボックスの種別が **必ず 武器/頭/胴 の順**に一致（17/17）。例 #37: 55→t22, 59→t23, 65→t24。**#37 と #41 だけ 3 点装備**。
* **0xFFFF = 未装備**。15 体が頭・胴 = 0xFFFF（**過去報告「0xFFFF が無し」は #37 だけを見た誤読**）。
* アイテム ID の解決も romfs と一致（例: #37 武器 id391 = `otWeaponData_jpn.gmd`「獰ホロロネコパラソル」、頭/胴 id464 = 「獰バンギスネコヘルム／メイル」で 3 点が揃う。#41 は id410「ディアＸネコハンマー」+ id457「ミラルーツネコヘルム／メイル」）。
  * 武器 ID: `otWeaponData` の文字列 **2×ID** が名前。
  * 頭/胴 ID: `otArmorData` の文字列 **4×ID**（頭名）, **4×ID+1**（胴名）— 頭と胴が**同じ ID**を共有するシリーズ ID 方式（#37 の 464/464、#41 の 457/457 が実例）。

### 3.6 出撃状態（+0xE0–0xE3）

実測: 0xE0 ∈ {32,33,34,**160**}, 0xE1 ∈ {0,4,5}, 0xE2 ∈ {0,8}, 0xE3 ∈ {0,2}。
C# の解釈（32=休憩, 33=1 枠目, 34=2 枠目, 40=モンニャン隊, 160=配信個体, 8=買い物中）と整合。**160 が配信 6 体にだけ出る**点が最良の裏付け。

## 7. 未確定（断定しない項目）

1. **+0x58–0x5E（7 B）の意味**。配信個体は 0、通常個体は非 0 で、同一作成元の個体で共通バイトがある。C# の「前オーナー ID(4B)+系統固有 ID(3B)」は未検証。固有 ID(0x5F) と合わせた個体識別子の一部と推定。
2. **+0xDC / +0xDE（各 u16、上位バイト常に 0）**。実測 0xDC∈{0,1,2,3,6,9,12,13,124,195}, 0xDE∈{0,3,4}。GMD の「あと / 回」表示との関連は推定。
3. **+0xE3 の意味**。実測 0/2。#41 のみ 2 で、C# の「1=ニャンター」とは値が合わない。
4. **+0x10E = 0x0F 固定**の意味。全 17 体で 15。GMD の「記憶力」（スキル装備上限）の候補だが、値が動かないため確定不可。
5. **テンション上限**。実測 25/99 のみ。99 が上限と推定（100 以上を観測していないだけ）。
6. **+0x54/0x56 のパターン ID が何を決めるか**。既知ペアとの一致は 17/17 だが、技/スキル習得内容との対応規則は不明（C# の「RNG 文字で習得セットを選ぶ」実装は修得数 8–12 件を説明できず、疑わしい）。
7. **技テーブル（58 件）の名前 GMD は未発見**。C# の英語名のみ。日本語名は romfs 上で特定できていない（開発バイナリ側の可能性）。
8. **+0x142（u16）**。0xFFF1/0xFFF7/0xFFF8 の 3 値のみで、名付け親と相関するが因果不明。
9. **色スロット 5/6（+0x12A / +0x12E）の割当**。GMD に「インナー」「防具の着彩」があるため候補だが対応未確定。

## 8. 実装メモ（`palico.rs` 拡張案）

```rust
// 追加で確定したオフセット（レコード相対）
pub const FORTE: usize = 0x25;        // u8  0..7 = カリスマ/ファイト/ガード/アシスト/ヒーリング/ボマー/コレクト/ビースト
pub const TENSION: usize = 0x26;      // u8  実測 25/99
pub const TARGET: usize = 0x27;       // u8  0..5
pub const EQ_MOVES: usize = 0x28;     // u8[8]   装備中サポート行動（0=なし, 57=空き）
pub const EQ_SKILLS: usize = 0x30;    // u8[8]   装備中オトモスキル（0=なし, 96=空き）
pub const LEARNED_MOVES: usize = 0x38;// u8[16]  修得サポート行動（0/57=空き）
pub const LEARNED_SKILLS: usize = 0x48;// u8[12] 修得オトモスキル（0/96=空き）
pub const UNIQUE_ID: usize = 0x5F;    // u8  0x97..0x9C = 配信個体
pub const EQUIP: usize = 0x100;       // u16[3] 武器/頭/胴（装備ボックス index, 0xFFFF=なし）
pub const EQUIP_BOX: usize = 0x17C2E; // slot 相対, 36B * 1000
```

* **空き値の扱い**: 技 = `0 || 57`、スキル = `0 || 96` を「なし」として除外するのが正しい（片方だけ除外すると件数がずれる）。
* **装備は ID 直値ではなく装備ボックスのインデックス**なので、名前を出すには `EQUIP_BOX + idx*36` の `+0 種別`（22/23/24）と `+2 item id` を読む必要がある。**未装備は 0xFFFF**。
* 系統 ID→表示名は romfs `OtInfoMsg_jpn.gmd` を正とする（8 種）。スキル名は `ot_skl_jpn.gmd`（文字列 2n = ID n の名前）。

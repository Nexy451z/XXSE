## 3. 特筆すべき発見

### 3.1 romfs の 33KB は「パディング」であって中身ではない（今回いちばん重要）

12 件すべてで、**ARC のディレクトリ直後からペイロード開始位置までが 0x00 で埋まっている**。
開始オフセットは全ファイルで **0x8000 (32,768)** に固定。

| ファイル | ファイルサイズ | ディレクトリ末尾 | ペイロード開始 | 0x00 パディング長 | 実データ（圧縮後合計） |
|---|---|---|---|---|---|
| q1011053 | 33,792 | 732 | 32,768 | 32,036 | **1,024 B** |
| q1020020 | 33,487 | 972 | 32,768 | 31,796 | 719 B |
| q1020030 | 33,321 | 972 | 32,768 | 31,796 | 553 B |
| q1110006 | 34,283 | 1,052 | 32,768 | 31,716 | 1,515 B |
| q1110113 | 35,315 | 1,292 | 32,768 | 31,476 | 2,547 B |
| （他 7 件も同様） | | | | | |

これは改造の痕跡ではなく、**無改変の romfs 抽出物（`extract/base_romfs/.../q1010001.arc`, 34,565 B）でも同じ**。
配信形式（`arcs/save_event/`）はパディングが無く、ペイロードがディレクトリ直後に詰まっている（1,733〜3,453 B）。

### 3.2 ダミー判定の「3 点セット」は 48 件中 31〜34 件、配信済み 175 件では 0 件

| マーカー | 未導入 48 件 | 配信済み 175 件 |
|---|---|---|
| 文字列 `Invalid Message` を含む | **32 件** | **0 件** |
| 成功条件が `dummy` | **33 件** | **0 件** |
| 報酬が `rem_000000` のみ | **31 件** | **0 件** |
| 名前に「予備」 | **31 件** | **0 件** |

「件数が合う」だけでは根拠にしない方針だが、**片側にしか出ないマーカー**であることは判定の後押しになる。
なお「予備」を含む名前は 31 件だが、うち 2 件（q1020030 / q1120013 の「予備枠」）は実報酬を持つ。
逆に報酬ダミー 31 件の内訳は「予備◯◯ 29 + 未使用 1 + 欠番 1」。つまり両者は**完全な同一集合ではない**（ほぼ重なるが別物）。

### 3.3 `rem_000000` は 48 ファイルすべてで完全に同じ

sha1 `6102128c8199…`、0x18 以降は全 0、非ゼロは先頭 3 バイト（`00 00 80 3f` とカウンタ）だけ。
→ 「報酬なし」を表す共通ダミー。**`rem_000000` しか無いクエストは報酬が 1 個も出ない**（`mhnx check` も WARN を出す）。

### 3.4 予備 6 件はテンプレート量産

- 6 件の `.qdl`（`questLink_<id>`）が**バイト単位で同一**。
- エントリ数 9 件・構成（`b_m00em000_00` / `z_m02d_008` / `z_m00d_000` / `rem_000000` / `supp_0000000` / `questPlus_0000` / `questLink` / `gmd` / `mib`）も同一。
- ファイルサイズが 33,790 / 33,792 / 33,793 に集中（差は `.gmd` の圧縮長の差だけ）。
  同フォルダには **33,786 × 7 件、33,789 × 6 件** の別クラスタもあり（他担当分）、
  「同サイズ多数」は量産データの目印として使える。

### 3.5 落とし穴: 闘技場イベントの報酬は「素材らしくない」のが正常

q1020020 / q1020030 の報酬（こんがり肉・ハチミツ・小金魚・生肉）は一見ダミーに見えるが、
**配信済みの闘技場イベント（q1020001 タマミツネ、q1020002 ディノバルド、q1020005 ラギアクルス、q1020015 紫毒姫 等）が
すべて同じ 4 点セット + `rem_400101/400201 = こんがり肉`** である。
→ この報酬内容は「闘技場イベントの標準」であり、**ダミー判定の根拠にはならない**。

### 3.6 マップ ID と .esl の整合は良い判別子になる

予備 6 件は map_id = 1/9 なのに `.esl` が `z_m02d_008`（森丘）。
一方、実クエスト側は map_id と一致している（q1110006: map 5 → `z_m05d_004`、q1110113: map 3 → `z_m03d_043/044/045`、
q1110107/1110110: map 104(=渓流&lt;夜&gt;) → `z_m04n_011`/`z_m04n_008`）。
`map_id` は 100 超で `-73` して読む仕様（`questfields.rs` の注記）。

### 4.1 サイズ: 12 件すべて 5,112 B に収まる（実測）

「ARC のオフセットをディレクトリ直後に詰め直すだけ」で作った `.arc` を実際に生成し、`mhnx check` と `arc-gmd` で検証した。

  33KB のままだと 0x13F8 を超えるので入らない、という点だけは依頼文のとおり。

### 4.2 中身の観点

| グループ | 導入 | 理由 |
|---|---|---|
| 通常イベント 5 件（q1020020, q1110006, q1110107, q1110110, q1110113） | **可（有意）** | テキスト・モンスター・報酬・アイコンが揃っており、チェックも通る。q1110113 は配信版と同一内容であることを確認済み |
| 没データ 7 件（予備 6 件 + q1020030） | **非推奨** | 予備 6 件は成功条件 `dummy`・ターゲット 0・報酬 0 なので、入れても「クリア不能／報酬なし」のクエストが 1 枠増えるだけ。q1020030 も成功条件 `dummy` でターゲット ID が不一致。**動作検証用に入れるのは可**（UI 確認など） |

### 4.3 q1020020 の注意点

依頼内容の武器種欄が `●●` 埋め。配信済みの同型 28 件は実名入りなので、
**「闘技場イベントとして配信される直前の下書きだった」可能性がある（推測）**。
ただし構造・報酬・モンスターは完全で、成功条件も「グラビモス１頭の討伐」と正常。
導入自体は問題なく通る（`mhnx check` ERROR 0）が、**表示上の武器種が読めない**点は利用者に伝えるべき。

### 4.4 導入時に確認すべき差分（推測を含む・要実機確認）

- `header8`（ARC +0x08）: romfs は `0xFFFFFFFE`、配信形式は `0x00000000`。
  詰め直しただけのファイルは `0xFFFFFFFE` のまま。**ローダがこの 4 バイトを見るかは未検証**。
- `.qdl` はロム版をそのまま流用して問題ない（q1110113 で配信版とバイト一致を確認済み）。
- セーブ枠は 1 枠 0x1400 ストライド・データ上限 0x13F8（`docs/review_catalogue.md` / `review_questloader.md` の記載と、
  `arcs/save_event/` の実サイズ 1,733〜3,453 B が整合）。

## 5. 判断できなかったこと（不明点として明示）

1. **「配信されなかった」のか「配信されたが手元にデータが無い」のかは区別できない。**
   ローカルの配信版ダンプは `arcs/save_event` 175 件 + `save_editor/mhxx_quetool/quest` 141 件分しかない。
   自分の 12 件では q1110113 だけが配信版ダンプに存在した。
2. **予備スロットが後から DLC で上書きされた可能性は否定できない。**
   観測例: `quetool/quest/q1011045.arc` のクエスト名は「ＭＨヒストリー三」で、
   romfs 側の同名 ID「ハンターＧ級予備４」と**別内容**（ただし内部 `.gmd` 参照名が `questData_1011043_jpn` とズレており、
   人為的に組み替えられたファイルの疑いもある）。この 1 例だけでは規則性を断定できない。
3. 「33,786 / 33,789 / 33,790 バイトが多数」というパターンは、**自分の担当 12 件でも
   33,790×3・33,792×1・33,793×2 として現れる**（残りは 33,3xx〜35,3xx）。サイズだけでダミー判定はできないが、
   同一サイズは「同じテンプレートから生成された」ことの傍証にはなる（3.4）。

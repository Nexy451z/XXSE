## 3. 候補と、断定できなかった理由

### 3.1 候補 A: 0x2D78 起点の高密度塊（称号ビットフィールド？）

| 項目 | 実測 |
|---|---|
| 164 B 窓 0x2D78..0x2E1B | **1,054 / 1,312 bit（80.3%）** |
| 172 B 窓 0x2D78..0x2E23 | **1,113 / 1,376 bit（80.9%）**（1,309 + 61 個の称号を 1 bit/個で持つ場合と同サイズ） |
| NEW（HR 0・7 分）の 1 の数 | **0**（同区間の非ゼロバイト 0） |
| スロット 1 | REAL スロット 0 と**バイト完全一致**（0x2C77..0x2DE7 で検証 True） |
| 前方境界 | 0x2D2A..0x2D77 が **78 B 完全ゼロ** → 0x2D78 から始まるのは確か |
| 直後の減衰 | 0x2E30 行の popcount 21、**0x2E40..0x2E77 は 56 B 完全ゼロ** |

**断定できない理由（3 点）**
1. **高密度部は 172 B で終わらない。** 0x2D78 から 0x2E37 まで（**448 B = 3,584 bit**）が高密度で、
   「172 B で切る」根拠が無い（172 B は母数から逆算した値であって、データが示した境界ではない）。
2. 同帯の 0x2C77..0x2C90（32 B、pop 122/128）、0x2CF0..0x2D00（16 B、pop 101/128）にも同種の
   高密度ブロックがあり、**独立した 1 フィールドとして切り出せない**。
3. 420 B / 324 B のような**外部の周期構造と一致しない**（0x2C00..0x3400 の自己相関は最高 0.135 で有意周期なし）。

→ 「称号の 80% が解放済み」という説明は**可能だが、それ以上の裏付けが無い**。
　**母数のサイズに合わせて切っただけなので、本プロジェクトの教訓（件数一致は根拠にならない）に照らして断定しない。**

### 3.2 候補 B: 14×420 B（0x22460..）— 称号ではない可能性が高い

自己相関 0.336 で周期 420 B が確定。rec01〜rec11 の NEW 非ゼロは **2 バイトのみ**（実質「新規キャラでは未解放」）。
ただし 14 という数は MHXX の**武器種数 14** と一致し、各レコードの形（先頭に 0x03/0x00/0x01… の小整数 + 後半にビット列）は
「武器種別の生産/強化フラグ」の方が自然。**推測**であり断定しない。称号 1,309 個を 14 で割ると 93.5 個/種で、
ビット列としても矛盾はしないため**完全否定もできない**。

### 3.3 勲章（132 bit = 17 B）について

- 132 bit ぴったりの 17 B 窓で「REAL の 1 が 40〜132 個・NEW が 0・前後バイトが 0」を満たすものは **1,447 箇所**（多すぎて絞れない）。
- その中で「17 B 中 14 バイト以上が popcount≥5 かつ合計 60 bit 以上」に絞っても **700 箇所**。統計的な区別がつかない。
- **勲章は「u8 1 個 = 0/1」「0x00/0xFF」のどちらでも存在しない**（§0.3）ため、ビット詰め以外の表現（例: u16 の ID 列、または
  「取得数 + 差分」形式）も視野に入れる必要があるが、**今回は特定できなかった**。

### 5.1 なぜ「決定打」が打てないか（正直な限界）

- ゲームを起動できないため、**「勲章を 1 個取る前後の差分」という唯一の決定的手法が使えない**。
- 手元の 2 人のキャラは**進行度が離れすぎており**（HR 967 / HR 0）、ビットフィールドの「どこからどこまで」を境界として読むには、
  間に位置する中間セーブが要る。スロット 1・2 は複製なので使えない。
- 母数（132 / 1,309）は分かったが、**「そのビット数に相当する領域を探す」手法は本プロジェクトの教訓（件数一致は根拠にならない）により採用していない**。

## 0. 先に結論

1. **オフセットの基準は「スロット基点からの相対」で統一されている**（例外は body 先頭のヘッダ 8 項目だけ）。
   `Offsets.cs` の全フィールドは `saveFile[player.SaveOffset + Offsets.X]` の形でしか使われておらず、
   `player.SaveOffset` は body+0x10/0x14/0x18 から読んだ**本体先頭からの絶対値**（0x126474 等）。
   したがって「フィールド = 相対 / 基点 = 絶対」の二段構え。**混同すると別領域を破壊する**（§1）。
2. 参照実装の UI は **キャラ 6 タブ + 6 ダイアログ**で、本ツールが未対応の領域は
   **装備ボックス（武器/防具）・オトモ装備箱・オトモ 84 体・ギルドカード・闘技大会・狩猟記録・シャウト**の 7 系統（§3）。
3. 参照実装には **移植してはいけないバグが 4 件**ある（スロット 3 削除の基点計算・B ランク書き込み・保存時サイズ膨張・護石レアリティ 0）。§4。
4. 逆に本ツールが**参照実装より正しい/多い**のは、名前プレビュー同時書き込み・性別プレビュー(0x2A)同時書き込み・設定（明るさ/振動/3D/パッド）編集・3DS 変換のヘッダ合成。
5. 参照実装も本ツールも**触っていない未開拓領域**が 2 つあり、うち 1 つは「アイテムマイセット 24 枠（170 B×24）」と推定できる（§5, §6）。

## 1. 最重要: オフセットの基準（スロット相対 / 絶対）

### 1.1 換算式

```
Switch のファイル絶対位置 = 36 + slot_base + rel
3DS のファイル絶対位置    =        slot_base + rel      （36 B ヘッダが無い）
body 絶対位置            =        slot_base + rel
```

- `slot_base` は **セーブ本体の中に書かれている** u32 LE（body+0x10 / +0x14 / +0x18）。
  このファイルでは 0x126474 / 0x244C34 / 0x3633F4（差分 = 0x11E7C0 = 1,173,440 B 一定）。**【実測】**
- 参照実装は Switch を読むとき `saveFile = saveFileRaw.Skip(36)`（MainForm.cs:92）と 36 B を落としてから
  以降の全処理を `saveFile` に対して行う。**つまり Offsets.cs の値は 36 B を含まない body 座標系**。
- 参照実装のコード上の根拠（全 44 使用箇所がこの形）:
  - `DataExtractor.cs:54,58,62,66,70,74,88-99,102,114,117,120-122,125,128-133`
  - `MainForm.cs:508,512,516-517,521,525-531,535-536,539-552,559-560,565-566,571-572,577-578,603,606,609,612,615-617,620,623,626-627`
  - 例外（スロット外・body 絶対）: `MainForm.cs:99-123,1279-1293`（0x04-0x06, 0x10-0x1B）

### 1.4 取り違えると何を壊すか（実測）

相対値を「絶対」と誤解した場合に実際に触る場所:

| 誤解した値 | 実際に触る場所 | 実測バイト | 壊れるもの |
|---|---|---|---|
| 性別 0x2A | body+0x2A = **配信オトモ #1 の名前先頭** | `e3 81 bd …`（「ぽかぽか」の「ぽ」） | 配信オトモ名 |
| 名前 0x23B7D | body+0x23B7D（DLC クエストセクション 0xB280 以降） | `00 00 00 …` | クエスト領域内のゼロ埋め（＝壊れたことに気付きにくい） |
| 装備箱 0x62EE | body+0x62EE（クエストセクション手前） | `00 00 00 …` | 同上 |
| ギルドカード 0xC71BD | body+0xC71BD（クエストセクション内） | `00 00 00 …` | 同上 |
| プレイ時間 0x20 | body+0x20（ヘッダの未使用 4 B） | `00 00 00 00` | 実害なし（＝逆に「効かない」で終わる） |

**規則**: 0x20〜0x62EE のような「小さい値」は必ず `slot_base` を足す。0x10〜0x1C と 0x04〜0x06 だけが足さない。

### 1.5 MHGU（英語版）に関する注意

`DataExtractor.cs:37-51 / MainForm.cs:1279-1293` は MHGU でも同じスロット相対値をそのまま使う。
MHGU はスロットストライドが 0x11F8C4（本ツール `save.rs:37`）で、スロット内の文字列長も違うため、
**MHGU に対してこの実装は成立しない可能性が高い【推測】**（本レポートの検証対象外。MHGU の実セーブが手元に無い）。

### やらない方がよい / 注意が必要

- **HR の直接書き込みの是非**: 参照実装は意図的に HR を読み取り専用にしている（HRP からゲームが導出するため）。
  本ツールは HR を直接書けるが、**HR だけ書いて HRP を据え置くと不整合になる可能性**【推測】。
  UI で HR を編集可能にするなら HRP との関係を注記するか、HRP 側の入力を促すべき。
- **参照実装の CleanSave 貼り付け方式のスロット削除**: 基点計算のバグ（D1）とテンプレート依存のため。
